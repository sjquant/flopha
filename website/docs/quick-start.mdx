# Quick Start

Run these inside a Git repository with an `origin` remote. flopha reads tags like `v1.2.3`.

## 1. Start from a tag

If the repository has no version tags yet, choose the first one:

```bash
flopha next-version --initial-version 0.1.0 --create --push
```

## 2. Calculate the next version

```bash
flopha next-version --auto
```

Breaking changes (`feat!:` or `BREAKING CHANGE`) bump `major`, `feat` commits bump `minor`, and everything else bumps `patch`. After a `feat: ...` commit on top of `v0.1.0`, this prints `v0.2.0`.

## 3. Create it

```bash
flopha next-version --auto --create --push
```

This creates the tag and pushes it to `origin`.

## 4. Release with one command

To also write the version into your manifests and publish a GitHub Release with a changelog, add a `flopha.toml`:

```toml
[release]
create = true

[[manifest]]
path = "package.json"
type = "npm"
```

Preview the plan, then release:

```bash
flopha release --dry-run
flopha release
```

Publishing the GitHub Release needs `GH_TOKEN` or `GITHUB_TOKEN`, or a local `gh auth login`. See the [`flopha.toml` reference](/docs/command-reference#flophatoml) for every option.
