# 명령어 참고 자료

## `flopha last-version` {/* #flopha-last-version */}

패턴에 일치하는 최신 버전을 출력합니다.

```bash
flopha last-version [--pattern <pattern>] [--source <tag|branch>] [--checkout] [--format <text|json>]
```

옵션:

- `--pattern`, `-p`: 사용자 지정 버전 형식에 일치하는 버전을 찾습니다. `{semver}`는 `{major}.{minor}.{patch}`로 확장됩니다.
- `--source`, `-s`: 태그 또는 브랜치에서 버전을 읽습니다. 기본값은 `tag`입니다.
- `--checkout`: 찾은 버전을 출력한 뒤 해당 버전으로 체크아웃합니다.
- `--format`, `-f`: 출력 형식입니다. `text`(기본값) 또는 `json`을 사용할 수 있습니다.

## `flopha next-version` {/* #flopha-next-version */}

다음 버전을 계산합니다.

```bash
flopha next-version \
  [--initial-version <MAJOR.MINOR.PATCH>] \
  [--increment <major|minor|patch>] \
  [--auto] \
  [--rule <level:regex>] \
  [--pre <channel>] \
  [--pattern <pattern>] \
  [--source <tag|branch>] \
  [--create] \
  [--tag-message <message>] \
  [--push] \
  [--format <text|json>]
```

옵션:

- `--initial-version`: 패턴에 맞는 버전이 없으면 접두사나 접미사 없는 `MAJOR.MINOR.PATCH` 값을 그대로 첫 버전으로 사용합니다. 일치하는 버전이 있으면 일반적인 버전 증가 규칙을 적용합니다.
- `--increment`, `-i`: 버전 증가 수준을 직접 지정합니다. 기본값은 `patch`입니다.
- `--auto`: 마지막 버전 이후의 커밋 메시지에서 버전 증가 수준을 판단합니다.
- `--rule`: 내장 자동 판단 규칙을 대체합니다. `--auto`가 필요합니다.
- `--pre`: `-alpha.1`, `-rc.1` 같은 접미사를 붙인 사전 릴리스 태그를 만듭니다.
- `--pattern`, `-p`: 사용자 지정 버전 형식으로 버전을 찾고 생성합니다. `{semver}`는 `{major}.{minor}.{patch}`로 확장됩니다.
- `--source`, `-s`: 태그 또는 브랜치에서 버전을 읽습니다. 기본값은 `tag`입니다.
- `--create`: 새 버전을 출력한 뒤 태그 또는 브랜치를 생성합니다.
- `--tag-message`: 지정한 메시지를 담은 주석 태그를 만듭니다. `--create`를 지정하고 버전 소스로 태그를 사용해야 합니다.
- `--push`: 생성한 태그 또는 브랜치를 `origin`에 푸시합니다. `--create`가 필요합니다.
- `--format`, `-f`: 출력 형식입니다. `text`(기본값) 또는 `json`을 사용할 수 있습니다.

## `flopha log` {/* #flopha-log */}

패턴에 일치하는 버전을 최신순으로 표시합니다.

```bash
flopha log [--pattern <pattern>] [--source <tag|branch>] [--limit <number>] [--format <text|json>]
```

옵션:

- `--pattern`, `-p`: 사용자 지정 버전 형식에 일치하는 버전을 찾습니다. `{semver}`는 `{major}.{minor}.{patch}`로 확장됩니다.
- `--source`, `-s`: 태그 또는 브랜치에서 버전을 읽습니다. 기본값은 `tag`입니다.
- `--limit`, `-n`: 표시할 행 수를 제한합니다.
- `--format`, `-f`: 출력 형식입니다. `text`(기본값) 또는 `json`을 사용할 수 있습니다.

## `flopha changelog` {/* #flopha-changelog */}

마지막 버전 또는 지정한 버전 이후의 커밋으로 변경 내역을 생성합니다.

```bash
flopha changelog \
  [--from <tag>] \
  [--to <tag>] \
  [--pattern <pattern>] \
  [--source <tag|branch>] \
  [--group <TITLE:REGEX>] \
  [--other <title>] \
  [--title <template>] \
  [--output <file>] \
  [--overwrite] \
  [--format <text|json>]
```

옵션:

- `--from`: 시작 태그입니다. 기본값은 패턴에 일치하는 최신 태그입니다.
- `--to`: 변경 내역을 어디까지 포함할지 정하는 기존 태그 또는 참조입니다. 이 값을 기준으로 커밋 범위를 제한하므로 Git에 실제로 존재해야 합니다. `--title`에서는 `{to}`로 참조할 수 있습니다.
- `--pattern`, `-p`: 사용자 지정 버전 형식에 일치하는 버전을 찾습니다. `{semver}`는 `{major}.{minor}.{patch}`로 확장됩니다.
- `--source`, `-s`: 태그 또는 브랜치에서 버전을 읽습니다. 기본값은 `tag`입니다.
- `--group`: `TITLE:REGEX` 형식으로 커밋을 묶을 규칙을 지정합니다. 여러 번 사용할 수 있습니다. 하나라도 지정하면 내장 기본 규칙을 모두 대체합니다. 어느 규칙에도 맞지 않는 커밋은 나머지 커밋을 위한 그룹에 모입니다.
- `--other`: 어떤 그룹에도 일치하지 않는 커밋을 모을 제목입니다. 빈 문자열을 전달하면 해당 커밋을 출력에서 완전히 제외합니다. 기본값은 `"Other Changes"`입니다.
- `--title`: 제목 템플릿입니다. 시작 태그는 `{from}`으로, `--to`를 지정한 경우 끝 참조는 `{to}`로 사용할 수 있습니다. 기본값은 `--to`가 있으면 `"Changes in {to}"`, 없으면 `"Changelog since {from}"`입니다. 아직 태그가 없는 다음 버전을 제목에 넣으려면 `--title`에 직접 지정하세요.
- `--output`, `-o`: 표준 출력 대신 파일에 기록합니다. 기본적으로 새 내용은 기존 파일 내용의 **앞에 추가됩니다**.
- `--overwrite`: 앞에 추가하는 대신 출력 파일을 덮어씁니다.
- `--format`, `-f`: 출력 형식입니다. `text`(기본값, Markdown) 또는 `json`을 사용할 수 있습니다.

### 기본 그룹 {/* #default-groups */}

`--group`을 지정하지 않으면 커밋은 다음과 같이 분류됩니다.

| 구분 | 일치하는 커밋 |
|---------|----------------|
| 호환성을 깨는 변경 | `BREAKING CHANGE`, `BREAKING-CHANGE` 또는 `type!:` |
| 새 기능 | `feat:` 또는 `feat(scope):` |
| 버그 수정 | `fix:` 또는 `fix(scope):` |
| 기타 변경 | 그 외 모든 커밋 |

### JSON 출력 스키마 {/* #json-output-schema */}

```json
{
  "title": "Changes in v1.2.0",
  "from": "v1.1.0",
  "to": "v1.2.0",
  "groups": [
    {
      "title": "Features",
      "entries": [
        { "subject": "add search command", "hash": "abc1234" }
      ]
    }
  ]
}
```

`to`는 `--to`를 지정한 경우에만 포함됩니다. 일치하는 커밋이 없는 그룹은 생략됩니다.

## `flopha release` {/* #flopha-release */}

`flopha.toml`을 사용해 릴리스를 준비하거나 게시합니다.

```bash
flopha release [--config <file>] [--initial-version <MAJOR.MINOR.PATCH>] [--prepare | --require-version-match] [--dry-run] [--format <text|json>]
```

- `--config`, `-c`: 저장소 루트 기준의 설정 파일 경로입니다. 기본값은 `flopha.toml`입니다.
- `--initial-version`: 첫 릴리스에 사용할 `[version].initial_version` 값을 재정의합니다.
- `--prepare`: 설정된 매니페스트만 수정하며 릴리스 PR을 위해 변경 사항을 스테이징하지 않은 상태로 남깁니다. 커밋, 태그, 푸시 또는 GitHub 릴리스는 생성하지 않습니다.
- `--require-version-match`: 매니페스트가 계산된 버전과 다르면 실패합니다. 일치하면 버전 변경 커밋 없이 게시합니다. 실제 릴리스에는 커밋된 파일이 필요합니다. `--prepare`와 함께 사용할 수 없습니다.
- `--dry-run`: 파일 기록이나 게시 없이 실행 결과를 미리 확인합니다. `--require-version-match`와 함께 쓰면 준비된 파일도 검증합니다.
- `--format`, `-f`: 미리보기와 릴리스 준비 결과의 출력 형식입니다. 기본값은 텍스트이며 JSON도 사용할 수 있습니다. 준비 결과를 JSON으로 출력하면 `{"version":"<tag>"}`이며, 수행할 작업이 없으면 `null`을 반환합니다.

`--prepare`와 `--require-version-match` 모두 `[[manifest]]` 대상이 하나 이상 필요합니다. 두 옵션을 모두 지정하지 않으면 `release`는 태그 생성과 게시 전에 매니페스트를 수정하고 커밋합니다. PR 준비 및 복구 절차는 [릴리스 워크플로](./release-workflows)를 확인하세요.

### `flopha.toml` {/* #flophatoml */}

모든 키는 생략할 수 있습니다. 파일을 비워 두면 아래 기본값으로 릴리스하며 GitHub 릴리스는 만들지 않습니다.

```toml
[version]
# initial_version = "0.1.0"            # used directly only when no matching version tag exists
pattern = "v{major}.{minor}.{patch}"   # default
auto = true                            # detect bump level from conventional commits (default)
# increment = "patch"                  # used instead of auto-detection when auto = false
# rules = ["major:BREAKING CHANGE", "minor:^feat"]
# pre = "beta"                         # pre-release channel, e.g. v1.2.3-beta.1
# tag_message = "Release {tag}"        # annotated tag message; supports {tag} and {version}

[changelog]
enabled = true
# groups = ["Breaking Changes:BREAKING CHANGE", "Features:^feat"]
# other = "Other Changes"
# title = "Changes in {to}"

[release]
create = true                         # default: false; publish a GitHub Release
draft = false
# title = "{tag}"                     # supports {tag} and {version}
# body = "..."                        # falls back to the generated changelog, then generate_notes
# generate_notes = false
# repo = "owner/repo"                 # defaults to parsing the `origin` remote

[[manifest]]
path = "Cargo.toml"
type = "cargo"                        # sets [package].version (or [workspace.package].version) and Cargo.lock

[[manifest]]
path = "package.json"
type = "npm"                          # sets the top-level "version" field

[[manifest]]
path = "pyproject.toml"
type = "pyproject"                    # sets [project].version, falling back to [tool.poetry].version

[[manifest]]
path = "docs/VERSION"
type = "regex"
pattern = "(?m)^version=.*$"
replacement = "version={version}"     # {version} is substituted with the new version
```

- 다시 실행해도 안전합니다. 이미 태그가 있는 커밋에서는 새 릴리스를 만드는 대신 해당 릴리스를 마무리합니다(태그를 푸시하고 누락된 GitHub 릴리스를 생성합니다). 새 커밋이 없으면 아무 작업도 하지 않습니다.
- 매니페스트 자동 커밋을 사용해 릴리스하려면 작업 트리가 깨끗하고 브랜치가 `origin`과 최신 상태로 동기화되어 있어야 합니다. 릴리스 커밋 푸시에 실패하면 로컬 커밋과 태그를 되돌립니다.
- `release.create`에는 `GH_TOKEN` 또는 `GITHUB_TOKEN`에 설정된 GitHub 토큰이 필요합니다. 로컬에서는 기존 `gh auth login` 인증도 사용할 수 있습니다.
- Cargo 워크스페이스를 대상으로 지정하면 `cargo metadata --no-deps --offline --locked`로 워크스페이스 버전을 상속하는 패키지를 찾습니다. 따라서 Cargo가 설치되어 있어야 합니다. 버전을 고정해 둔 멤버는 변경하지 않습니다.
- `version.source = "branch"`는 지원하지 않습니다. 브랜치 기반 버전 관리에는 `flopha next-version --source branch --create`를 사용하세요.

## 공통 동작 {/* #global-behavior */}

- `--verbose`, `-v`는 디버그 로그를 활성화합니다.
- CLI는 버전을 확인하기 전에 `origin` 원격 저장소에서 변경 사항을 가져옵니다(fetch).
- 기본 버전 패턴은 `v{major}.{minor}.{patch}`입니다. 같은 의미의 축약형 `v{semver}`도 사용할 수 있습니다.

패턴에 일치하는 버전이 없으면 초기 버전을 지정하지 않는 한 `next-version`과 `release`는 실패합니다. `--auto`는 초기 버전을 선택하지 않습니다. 앞에 0이 없는 부호 없는 32비트 정수 세 개를 사용해야 하며 태그 접두사, 사전 릴리스 접미사, 빌드 메타데이터는 넣지 마세요. 사전 릴리스에는 `--pre` 또는 `version.pre`를 사용하세요. 예제는 [첫 릴리스](./release-workflows#first-release)를 확인하세요.
